The fact memories an agent can mount, declared in one file.

AGENTS.md tells an agent how to behave. ENGRAMS.md declares what it can know: the detachable fact memories — cartridges — it may mount, what questions each one answers, which exact model stack each is bound to, and how well each has been measured to recall its own contents.

Why a file

Because a cartridge makes promises no other memory can

Enumerable, so auditable

Every fact went in through a canonical line, so every fact can be regenerated and checked. audit.accuracy is a statement about the whole store, not a sample.

Stack-bound, so declared

A cartridge is trained against one exact model stack and mis-recalls elsewhere. The file carries the fingerprints; runtimes refuse mismatches.

Query shapes, not vibes

A cartridge answers the key formats it was compiled for. The file tells the agent exactly what it may ask — and the agent writes those keys itself.

Detachable, so provable

Mounts in milliseconds; unmounts leaving the base byte-identical. Knowledge that is gone, not suppressed.

Resident, so free

Facts influence generation at every token without spending context — no retrieval round trip, no payload in the prompt or the logs.

Honest about failure

Audits ship their miss lists; a provenance signal tells silent from active; security profiles say plainly that a public cartridge is a compiled extract of public facts.

Adopt it

Three steps

  1. Compile and audit. Turn your facts into canonical lines, train a cartridge against your frozen base, audit it whole, repair, stamp. A 16,000-fact store audits in about 80 seconds on one GPU.
  2. Declare it. Write ENGRAMS.md at your project root: name, query shapes, stack fingerprints, audit, file checksum. Run tools/validate.py.
  3. Mount by fingerprint. Your agent reads the file, mounts the cartridge that matches its stack, asks only in the declared shapes — and, if you want, shows a provenance badge on every answer. The demo's chat workspace is a working pattern: the model writes the key, the memory answers it, the model phrases the value.

Runtimes exist today for native inference and for the browser (wasm) — the live demo runs the latter — both implementing engram-gguf/1 with bit-exact hashing parity.

FAQ

Questions people ask first

Isn't this just a key-value store with extra steps?

For a single pre-resolvable key, a dictionary wins and the spec says so. A cartridge earns its place when facts must be resident during generation: many facts per answer, unpredictable which ones, mid-stream, offline, or shaping token-level syntax — with zero context tokens and no retrieval service. And it is the only memory format whose recall can be audited per fact.

Does a cartridge understand paraphrase?

No. Recall is bound to exact key tokens. The model does the understanding — it writes the canonical key — and the memory recalls exactly. That division is the design, not a limitation to hide.

Can I mount several cartridges at once?

Today's measured answer is "one memory at a time, chosen by a router": independently trained cartridges with overlapping vocabularies interfere when co-mounted. The chat pattern routes naturally — the key format the model writes identifies the cartridge. Co-training for true co-mounting is a named open item.

Is a cartridge file private?

No. It is a compiled extract of its facts: with the hash seeds in the file, an attacker who can guess keys can reconstruct values offline (measured: 42% of sampled facts from a public cities cartridge, no model loaded). Publish only public facts under profile: public; use the pseudonymous profile — keyed-hash keys with a mount-time secret — for anything else.

How is this related to DeepSeek's and Qwen's engrams?

The mechanism is DeepSeek's Conditional Memory via Scalable Lookup, now shipping inside models such as Qwen3.8-Flash-Next. ENGRAMS.md is the convention for detachable, auditable engrams trained after the fact — cartridges, manifests, registries. A complement, the way AGENTS.md complements the models it instructs.

Why plural?

Because a project has several memories, the way it has several agents. One file declares them all.
